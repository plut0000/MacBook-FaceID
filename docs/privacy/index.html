Privacy

Face Unlock is local by design. Camera frames, embeddings, and your login password stay on this Mac. This website is static documentation; the app does not phone home.

No telemetry

The app has no analytics, accounts, crash uploader, or cloud sync. There is no network requirement for Face Unlock to run. This GitHub Pages site is separate from the app: opening the site in a browser is ordinary web traffic to GitHub, not something the Mac app does.

Camera frames

Frames are processed in memory to enroll and to watch for a match. They are not written to disk and they are not uploaded. During enrollment, each accepted frame becomes a 512-number embedding and the image is thrown away.

What is stored on disk

  • Encrypted identity embeddings (not photos) in an AES-256-GCM vault under Application Support (~/Library/Application Support/MacBookFaceID/).
  • Your macOS login password, encrypted in that same vault — never as plaintext on disk.
  • A 256-bit vault key in the login Keychain, access-controlled with userPresence (Touch ID or device password). The key is held in memory only while a session is authorized.

The default embedding engine is an original 512-d vector of a 112×112 aligned face. This project does not bundle someone else’s ArcFace .mlpackage. If you drop your own redistributable Core ML model into Application Support, that file is also local to this Mac.

Erase

Settings → General can erase enrollment and the vault. That removes the vault files and the Keychain key immediately. You can also delete individual identities under Your Face without wiping the whole vault.

What this is not

On-device does not mean Secure Enclave Face ID. A process running as you, with an authorized session and Accessibility, can type the same password. Grant Accessibility only if you accept that this app can post keyboard events. Details and first-run steps are on setup.

Source: github.com/plut0000/MacBook-FaceID.
